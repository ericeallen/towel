# Security Policy

| Version | Supported          |
| ------- | ------------------ |
| 0.6.x   | :white_check_mark: |
| < 0.6   | :x:                |

## Reporting a Vulnerability

We take the security of Towel seriously. If you believe you have found a security vulnerability, please report it to us as described below.

### Please do NOT:

- Open a public GitHub issue for security vulnerabilities
- Disclose the vulnerability publicly before it has been addressed

### Please DO:

1. **Report via GitHub Security Advisories**:
   - Go to https://github.com/ericeallen/towel/security/advisories
   - Click "Report a vulnerability"
   - Provide detailed information about the vulnerability

2. **Or report via email** (if you prefer):
   - Email details to: [Provide contact email if desired]
   - Include "SECURITY" in the subject line
   - Provide detailed information about the vulnerability

### What to include in your report:

- Description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Suggested fix (if you have one)
- Your contact information for follow-up

### What to expect:

- **Initial Response**: We will acknowledge your report within 48 hours
- **Status Updates**: We will keep you informed about our progress
- **Fix Timeline**: We aim to release fixes for verified vulnerabilities within 30 days
- **Credit**: We will credit you in the security advisory (unless you prefer to remain anonymous)

## Security Considerations for Towel

### Code Analysis Tool

Towel is a static code analysis and refactoring tool. Security considerations include:

1. **Arbitrary Code Execution**: Towel parses and analyzes Python code using the `ast` module. While it does not execute the code during analysis, users should only run Towel on trusted codebases.

2. **File System Access**: Towel reads and writes Python files in the directories you specify. Ensure you have backups and use version control.

3. **Generated Code**: Always review the refactored code generated by Towel before committing it to production. Run your test suite to verify correctness.

### Best Practices

- **Use Version Control**: Always commit your code before running Towel
- **Review Changes**: Carefully review all proposed refactorings
- **Run Tests**: Execute your full test suite after accepting refactorings
- **Backup Data**: Maintain backups of your codebase
- **Trusted Sources**: Only analyze code from trusted sources
